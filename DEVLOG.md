## Day 1, session 1 (setup, Core engine, bots, tests)
- Built:
  - Installed NAV MCP 1.0.2 (arm64 .dmg from GitHub Releases, sha256 checked), linked the project by hand, connected to the daemon over HTTP.
  - `Assets/_Project/Scripts/Core` (own asmdef, `noEngineReferences`): cards, deck, hand, `RulesConfig`, `TarneebRules`, `TarneebEngine` (commands in, events out, no throwing for illegal moves), `HeuristicBot`, `CardTracker`, `HandEvaluator`, `BotRunner`.
  - EditMode tests (42 at the end of Day 1): deck/deal/determinism, bidding validation and end conditions, follow suit, trick winner, scoring, game end, full bot rounds, and the headless simulation (10,000 games).
- Decisions:
  - Unity: the project was created on **6000.6.3f1** but the plan says 6000.3.x. NAV MCP 1.0.2 does not compile on 6000.6 (about 50 `CS0619` errors, see field notes), so I installed **6000.3.25f1** with WebGL support through Unity Hub's CLI and downgraded the project: removed the 6.6-only modules (`physicscore2d`, `tetgen`, `timelinefoundation`) and pinned URP 17.3.0 / ugui 2.0.0 / test-framework 1.6.0 / input system 1.14.2 in `manifest.json`. Later the WebGL build failed because the URP global settings asset was one version ahead (11 vs 10); I fixed that with a serialized-property edit through `unity_script`, not by hand.
  - Seat order: seat `s+1` plays after seat `s` when `Counterclockwise` (default). On screen that puts the next player on the local player's right (bottom, right, top, left), `SeatMapper` does the mapping so the engine never knows about screen positions.
  - Bidding ends when three players have passed after a bid, exactly as specified. A bid of 13 does not short-circuit; the other players just get Pass as their only option.
  - `RedealOnAllPass = false` is implemented as "the dealer is stuck with the minimum bid" (the plan only says the config exists).
- Bugs found / fixed:
  - Bot bidding was far too timid: with `PartnerAllowance = 3` there were **2.2 all-pass redeals per round** and 93% of contracts were made. I swept 3.0-6.0 (1,500 games each): 5.0 gives 0 redeals, 74% made, average bid 7.7. Set as the default.
  - Kaboots never happen in the simulation (0 of 91,849 rounds). Bots bid conservatively at the top end; left as is (a human can still do it).
- AI output rejected or corrected:
  - My first heart icon (generated with two ellipses and a triangle) looked wrong; regenerated with tangent circles and checked the PNG visually.
  - Plan said DOTween. It is an Asset Store / website download with a form, so I wrote a 100-line coroutine tween (`Tween.cs`) instead. Same feel, no licence or import risk. **Reviewer decision:** swap in DOTween later if you prefer.
- Needs developer review: seat direction mapping above; bot tuning numbers.

## Day 2, session 2 (Unity layer, scenes through NAV MCP)
- Built:
  - `Scripts/Game` (`GameController`, `MatchLoop`, `SeatController` family) and `Scripts/Presentation` (`TableView`, `HandView`, `CardView`, `SeatView`, `HudView`, `BidPanel`, `TrumpPicker`, `RoundSummaryView`, `GameOverView`, `Tween`, `AudioManager`, `FitScale`).
  - Cards, suit icons, card back, panels and six sound effects are original and generated by `Tools/gen_art.py` (CC0). No third-party assets at all.
  - Game and Menu scenes and the `CardView` prefab are generated through NAV MCP batches by `Tools/build_scenes.py` (about 130 GameObjects, ~500 ops).
  - Animation queue: the engine resolves instantly; the loop only asks a seat to act after the table has finished presenting every queued event.
- Decisions:
  - Cards are uGUI (rank text + suit icon sprites), not baked sprites, so they stay crisp at any resolution and the WebGL build stays small (**11.3 MB**).
  - `FitScale` letterboxes the 1080x1920 design frame inside any window, so the desktop browser shows a centered portrait table.
  - When only one card is legal the game plays it after 0.45 s (still animates), so tapping is never wasted.
- Bugs found / fixed (all found by rendering the Game scene from a PlayMode test to PNG, since NAV MCP cannot take a screenshot):
  - Hand cards rendered 3x too large. Cause: NAV's `gameobject.create` keeps the world transform when parenting, and my `[ExecuteAlways]` `FitScale` had scaled the parent in edit mode, so children got a compensating scale. Removed ExecuteAlways and added a scale-reset pass to the generator.
  - `GameOver`/`RoundSummary` views were two MonoBehaviours in one file (`Popups.cs`); Unity could not resolve the second one on the scene object. Split into one class per file.
  - Side seats were clipped at the screen edge; trick cards overlapped too much. Adjusted seat width (260), positions (+-355) and trick offsets, re-rendered and checked.
  - `WaitForEndOfFrame` does not run in batch mode; the screenshot test now renders with `Camera.Render()`.
- AI output rejected or corrected: `sed -i` without `''` on macOS (BSD sed) twice; chained shell commands that outlived the tool timeout and killed my own Editor; `pkill -f` patterns matching the command line of the shell that ran them. Now wrapped in `Tools/*.sh`.

## Day 3, session 3 (tests, WebGL, online layer)
- Built:
  - PlayMode tests: all-bots game (no presentation), **a full game played through the real UI widgets** (button clicks and card taps), screenshot renders of every phase.
  - WebGL: custom template (fills the window, loading bar, fullscreen button), Brotli with decompression fallback, managed stripping Medium, `build.validateTarget` 0 errors / 0 warnings (6 warnings before I set the WebGL sample-rate overrides on the SFX).
  - Online multiplayer (disabled): replica-engine design, host/client, loopback transport, 8 tests, Photon transport and lobby behind `PHOTON_UNITY_NETWORKING`. See `Assets/_Project/Scripts/Net/README.md`.
- Decisions:
  - Multiplayer sends accepted *commands* and a replica engine on each client re-derives every event, instead of serializing state or events. That is why the same `TableView` works online with no changes, and why hidden hands are trivially private.
  - `LocalIsBot` / `SkipPresentation` static test hooks let the same `GameController` run unattended in tests.
- Bugs found / fixed:
  - `RemotePlayerController` kept a consumed request and replayed it forever (1.5 million rejected commands in one test run). Fixed and the test now guards it.
  - A remote request can arrive before the match loop has finished animating and called `Begin`; requests are now buffered instead of dropped (otherwise the 15 s timer would hand the seat to a bot).
- Needs developer review: see the list at the bottom of README.md ("Known limitations").
